# 架构

三块，各管一段，中间只有 HTTP：

```
web/index.html  ──HTTP──>  src/server.py  ──HTTPS──>  api.typesafe.ai
录音 · 倒计时 · 结算        代理 · 识别转发 · 缓存        Jev
```

| 路径 | 职责 |
| --- | --- |
| `src/game.py` | 纯逻辑：规则、交给 Jev 的 `state` 原文、从信念到出拳的算术、语音文本解析 |
| `src/server.py` | 本地服务器：代理 Jev、识别转发、静态页面、缓存 |
| `web/index.html` | 页面，单文件零外部依赖：倒计时与音效、牌桌、记忆、语音接线 |
| `tests/` | 上面两个 Python 文件的测试，不联网 |
| `var/` | 运行时产物（识别的本地缓存），已 gitignore |

## 逻辑层为什么单独一层

`src/game.py` 里没有网络、没有磁盘、没有时钟，全是入参到出参的函数。所以这个游戏里
唯一值得单独测的部分可以全部单测覆盖，而 `server.py` 只剩下接线和重试这类不容易写错的
东西。

## 一次出拳的数据流

1. 点「开始」：页面**同时**启动倒计时和 `POST /api/decide`，两件事并排跑。
2. 服务器把已完成的历史写成 `state`（[怎么写](jev.md)），带上带类型的问题发给 Jev。
3. Jev 回一组信念分布，外加它顺带直接选的那一手。
4. `choose_throw` 在规则之内挑期望净胜分最高的那一手。
5. 倒计时结束、你喊出这一手、两边都齐了，才开牌。

关键在第 1 步和第 3 步的次序：**Jev 在你开口之前就已经把出拳定死了**。它拿到的是
历史，不是这一回合 —— 它没有可以「偷看」的入口，这不是纪律问题，是没有通路。

失败会停下来说清楚，并给一个「重试这一局」；重试拿的是**同一份历史**，
Jev 仍然看不到你出了什么。

## 密钥边界

- 密钥只在服务器进程里，浏览器只跟 `127.0.0.1` 说话，页面拿不到 key。
- 历史只存在浏览器内存里，刷新页面就没了 —— 没有做持久化。

## 测试

```bash
python3 tests/test_game.py && python3 tests/test_server.py
```

含重试预算、缓存、以及不联网的那部分 HTTP 层）。
