# 语音

按顺序试两条路，第一条通了就不试第二条：

1. **浏览器内置**（Web Speech API）。零配置。但它走 Google 的服务器，
   **中国大陆的 Chrome 用不了**，会直接报服务不可用。
2. **服务器端识别**。浏览器把音频录一段丢给 `/api/asr`，由你配的命令转写。
   这条能在中国大陆用。

配第二条（以阿里云百炼的 `bl` 为例）：

```bash
bl auth login --api-key "$DASHSCOPE_API_KEY"        # 先装好 bl
export I_SHOOT_ROCK_ASR_CMD='bl speech recognize --url {wav} --output json'
python3 src/server.py
```

`{wav}` 会被换成临时音频文件路径，命令经由 shell 执行，**往 stdout 打一行文字**即可。
如果那个工具打的是 JSON，接一个抽取：

```bash
export I_SHOOT_ROCK_ASR_CMD='bl speech recognize --url {wav} --output json | jq -r .text'
```

> 这条路径的**接线**是实测过的：用假麦克风 + 一个 `printf '石头剪刀布，剪刀'` 的假识别器
> 跑通了「音频 → 端点检测 → /api/asr → 文字 → 出拳 → 结算」全程。
> 但 **`bl` 本身没在这里验证过**（这个环境里没装 `bl`，也没有 DashScope 密钥），
> 所以上面那条命令的子命令和输出形状需要你按 `bl --help` 核一下。

两条都不通也能玩：倒计时期间和之后都能点按钮出拳。

## 端点检测：听到停顿就停

服务器端识别靠自己算音量做端点检测：声音起来就开录，**一听到停顿就停止录音** ——
静满 0.52 秒就把这一段发去识别，不用手动按开始/结束，也不用等一个固定的时长。

门槛不是写死的音量，而是跟着房间的本底噪声走（固定阈值在安静的房间里等不到停顿，
在吵的房间里又等于没有）。本底用不对称的滑动平均跟：房间安静下来时立刻跟下去，
变吵时每帧只挪一点点 —— 对称的均值会被一声咳嗽、一次键盘顶上去，门槛就再也降不回来，
而那正是这个功能最怕的：人喊了「石头剪刀布」，它却听不见。

连续 80 毫秒才算真的开口（挡掉单帧的响动），最长录 8 秒，短于 260 毫秒或小于 1.2 KB
的片段不值得发出去，直接丢掉。录音时话筒旁边有个红点，停下来的那一刻会写
「听到停顿，已停止录音」。

## 「石头剪刀布」里含着三种出拳的名字

这是语音部分最容易错的地方：「石头剪刀布」这五个字里同时有石头、剪刀、布。
不管的话，一句口诀会被当成出了三次拳。

所以口诀先被剥掉，**剩下的部分里最后一个出拳词**才算数：

| 听到 | 出拳 |
| --- | --- |
| 石头剪刀布 | 没有（只是口诀） |
| 石头剪刀布，剪刀 | 剪刀 |
| 石头剪刀布，我出布 | 布 |
| 石头，不对，布 | 布（取最后一个，允许改口） |
| 剪子 / 锤子 / 包袱 | 剪刀 / 石头 / 布 |

这段逻辑在 `src/game.py` 的 `parse_utterance`，有 14 个用例盯着它。

## 认音，不认字

识别器是按音写字的，而且每次挑的同音字还不一样：喊「布」，它写「不」。
只按字面比对就会漏掉 —— 这是实际用起来第一个卡住的地方。

所以字面之前还有一层**读音**：先把字还原成音节（自带一张十来组音的小表，
只收这个游戏用得到的音，不引拼音库），再把音节收敛到「音类」再比 ——
翘舌/平舌（`zh/ch/sh` → `z/c/s`）、前后鼻音（`ang/eng/ing` → `an/en/in`）
是识别器最常混的两组。

| 听到 | 出拳 |
| --- | --- |
| 不 / 步 / 部 / 埠 / 补 | 布 |
| 时头 / 十头 / 全头 / 吹子 | 石头 |
| 尖刀 / 剑刀 | 剪刀 |
| 包伏 / 包服 | 布 |

要紧的是别把「不对」的那个「不」当成布：`不` + `对/是/要/行/知/好/会…`
一律不算出拳，所以「石头，不对，布」还是布 —— 用户改口的那句不能反客为主。

口诀也一并按读音抠掉：识别器把口诀末尾的「布」写成「不」时（「石头剪刀不」），
那仍然是口诀，不是出了布，也不是出了剪刀。

`不`、`卜` 之外的同音字没有这个歧义，直接就是出拳。读音层没有结论时，才退回字面匹配 ——
英文的 `rock` / `paper` / `scissors` 走的就是这条。
